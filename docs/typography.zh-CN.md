# 字有读者

Dr Non 对 Robert Bringhurst《The Elements of Typographic Style》的读法。用的是第二版、1997 年印次，选读，不是通读。

第三条法把字号和行距绑在一起。那三档是我们选的系统，不是 Bringhurst 的普遍规则，也不是 MoMA 的字。可执行的那条法留着。在宣布工作做完之前，先补上这一页面向读者的证明。

## 步骤

1. 读真正的文本。说出读者在做什么、媒介是什么、文种是什么、项目里已有的字体政策是什么。把标题、段落、动作、说明、错误这几个角色画出来。
2. 先证明被批准的正文字体。一张标题脸，不能因为它戏剧，就变成正文。一种家族若盖得住真实的角色，就留一种。
3. 比较搭配时看比例、笔画粗细的对比、看起来的大小、节奏，不要只看衬线或无衬线这个标签。一种搭配需要一个角色，以及合同允许。
4. 把字号、行距和行长、间距放在一起。用真实的行，不要用「66ch 适合一切散文、一切文种」这条规矩。CSS 的 `ch` 是零字的宽度。
5. 拉丁文的大小写和字距，跟泰文、中文的规矩分开。检查叠标、标点、断行、文种覆盖。房子的合同撑不住的地方，去要一份写明范围的例外。请读得顺的人来看。
6. 在手机宽度、放大的文字、字体被挡住、真实的颜色、以及手头有的字重上做证明。记下失败的，不只记下检查器通过的。

## 收据

读者、任务、媒介；真实内容；按角色批准的字体家族；实际的字重和许可；回退；被拒绝的替代方案和看见的理由；字号、行距、行长；证明的条件和失败；例外；还等着读得顺的人、或人来审的任务。

一段读不下去、又必不可少的说明，挡住发布。把失败的标本拿出来，去要一份写进项目的例外。不要悄悄加第四档字号，也不要声称第三条法保证能用。现有的 `type-scale` 核对的是记号的纪律，不是排印是否合适，也不是人是否写过这段字。

它只匹配光秃秃的 `font-size: Npx`。它不读 `line-height`，也看不见 `clamp()`。`lint/laws-check.mjs` 能从 `micro 11/16` 里捕获行距，却从不拿它去比 `lint/scale.mjs` 里的 `LEADING`。

## 演示页实际设的

2026-10-12 渲染，视口 1280×900。正文是 IBM Plex Sans，14px / 20px，这是正文那一档。标题是 `clamp(32px, 7vw, 64px)`，`line-height: 1.02`，算出来是 64px / 65.28px，字重 700。这是第四档。同一天 `node lint/moma-lint.mjs examples --strict` 报告 0 条违规。第三条法没有失败，因为检查器看不见这个声明。

那一页上的微标签是大写的，还加了字距。MoMA 的机构声音不这么做，见 [moma-vs-us.md](moma-vs-us.md)（英文测量记录）。泰文和中文不继承拉丁文的字距和大小写。一份把泰文拉开字距、或把中文改成全大写的译文，已经在这一页要保护的那个读者身上失败了。
