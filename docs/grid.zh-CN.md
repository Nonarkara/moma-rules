# 网格，推出来的

这一页上没有偏好。每个数都从四个起点推出来，而且推法可以核对。

核对的命令是 `node lint/self-check.mjs`。它证明 `lint/scale.mjs` 内部一致。它不读这一页。

## 四个起点

```
栏数     12
栏宽     88px
槽       16px
页边     24px
```

## 这一页

```
  12 栏 ×  88px   = 1056
+ 11 槽 ×  16px   =  176
─────────────────────────────
  内容宽           = 1232
+  2 页边 × 24px   =   48
─────────────────────────────
  页宽             = 1280
```

1280 不是因为「桌面常用这个宽度」才被选中。它是选定栏宽 88（= 4 × 22）和槽 16 之后 **落出来的**。若栏宽选 80，页宽就是 1184。要点是页宽是结果，不是输入。所以内容不必被挪一下才能塞进去。

## 为什么是十二

十二是最小的、又有四个非平凡因数的有用数字：2、3、4、6。每一个都给出 **整数** 跨栏：

| 你要 | 跨栏 | 宽度 | 核对 |
|---|---|---|---|
| 十二分 | 1 | 88 | 12 × 88 + 11 × 16 = 1232 |
| 六分 | 2 | 192 | 6 × 192 + 5 × 16 = 1232 |
| 四分 | 3 | 296 | 4 × 296 + 3 × 16 = 1232 |
| 三分 | 4 | 400 | 3 × 400 + 2 × 16 = 1232 |
| 二分 | 6 | 608 | 2 × 608 + 1 × 16 = 1232 |
| 满 | 12 | 1232 | 1 × 1232 = 1232 |

`跨栏(s) = s × 88 + (s − 1) × 16`

每一行都恰好回到 1232。没有余数要去吸收，所以没有组件需要「挪一下」。1px 的漂移就是从挪一下来的。

## 密度，推出来的

响应式网格通常写成 `repeat(auto-fit, minmax(Xpx, 1fr))`，而 X 通常是用眼睛挑的。这是大型代码库里错位的最大单一来源，因为每个 X 都会落到自己的列数。

修法是只允许那些 **本身就是跨栏宽度** 的 X。在每个常见视口上核对过（768 以下页边为 16，以上为 24）：

| minmax | 390 | 768 | 1024 | 1280 | 1440 | 整除 12？ |
|---|---|---|---|---|---|---|
| 88（跨 1） | 3 | 7 | 9 | 12 | 13 | **否** |
| **192**（跨 2） | 1 | 3 | 4 | 6 | 6 | 是 |
| **296**（跨 3） | 1 | 2 | 3 | 4 | 4 | 是 |
| **400**（跨 4） | 1 | 1 | 2 | 3 | 3 | 是 |
| **608**（跨 6） | 1 | 1 | 1 | 2 | 2 | 是 |

四种合法密度。每一种、在每一个宽度上，都落到能整除 12 的列数。所以格子的边落在主栏线上，十二件的一组能填满它而不留空格（第四条法）。

跨 1（88px）被排除：它给出 7 列和 13 列，没有东西能跟它对齐。十二栏是 *作图* 的网格。它不是合法的 auto-fit 密度。

列数的算法，和 `lint/self-check.mjs` 用的是同一个：页边在视口小于 768 时为 16，否则为 24；列数是 `max(1, floor((视口 − 2 × 页边 + 槽) / (下限 + 槽)))`。

## 对照：代码库今天在做什么

daytraders 用了 **31 个不同的 minmax 下限**——5、38、42、56、64、72、78、88、90、92、96、100、104、110、118、120、130、140、150、160、180、190、200、220、240、260、280、300、320、360、440——在一张 1280px 的页面上产出 **12 种不同的列数**。5、7、9 列的节无法和任何东西共享一条内部的边，也没有一种能在不留空格的情况下填满。

这些数来自 2026-09-08 的测量记录，不是这一版重测的。

## 窄屏

768 以下，页边降到 16，栏变成流动的：

```
栏宽 = (100vw − 32 − (列数 − 1) × 16) / 列数
```

*栏* 是流动的。**槽和页边留在刻度上。** 这条线要守住：流动的宽度可以，流动的间距不行，因为间距是相邻两个组件必须达成一致的东西。

## 写成 CSS

```css
:root {
  --col: 88px;
  --gutter: 16px;
  --margin: 24px;
  --content: 1232px;

  --span-2: 192px;   /* 六分 */
  --span-3: 296px;   /* 四分 */
  --span-4: 400px;   /* 三分 */
  --span-6: 608px;   /* 二分 */
}

.page {
  max-width: var(--content);
  margin-inline: auto;
  padding-inline: var(--margin);
}

/* 仅有的四种合法响应式网格 */
.grid-sixths   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-2), 1fr)); }
.grid-quarters { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-3), 1fr)); }
.grid-thirds   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-4), 1fr)); }
.grid-halves   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-6), 1fr)); }
```

## 发丝线网格，做对的那种

`gap: 1px` 铺在有颜色的背景上，用来画出每一条内线，这个办法很好，应当留下。变的只是外框——第一条法：

```css
/* 错——边框把每个子元素推开 1px */
.hairline-grid { display: grid; gap: 1px; background: var(--line);
                 border: 1px solid var(--line); }

/* 对——框画出来，但不占布局 */
.hairline-grid { display: grid; gap: 1px; background: var(--line);
                 box-shadow: inset 0 0 0 1px var(--line); }
```

两个画出来的框一样。只有第二个把子元素留在页面的原点上。

## 演示页实际铺出来的

上面的 CSS 就是 `examples/index.html` 在用的。那个文件还对每个元素设置了 `box-sizing: border-box`。2026-10-12 测过，无头 Chrome，视口 1280×900，深色：页面边框盒是 1232px，左右各垫 24px，内宽是 1184px。

`lint/scale.mjs` 仍说页宽是 1280：内容 1232 加上两个 24 的页边。在 `border-box` 下，边框盒要成为 1280，`max-width` 必须是页宽 1280，而不是内容宽 1232。这一页的算术是源头。演示文件还没有把页面铺成 1280。静态检查器不看 `max-width`，所以 CI 仍然是绿的。
