# ทำไมเส้นยังไม่ตรง

*บันทึกการวัด ทุกตัวเลขที่นี่วัดบนของจริงเมื่อ 2026-09-08 ไม่ใช่การประมาณ ฉบับนี้ไม่ได้ไปวัดไซต์นั้นซ้ำ*

คำถามของ Dr Non: **«บางครั้งฉันพูดกฎ MoMA แล้วระบบยังยอมให้มีเส้นที่ไม่ตรงกัน ทำไม»**

มีห้าคำตอบ มีแต่ข้อแรกที่เกี่ยวกับวินัย อีกสี่ข้อเป็นกลไก ซึ่งเป็นเหตุที่การพูดคำเหล่านั้นไม่เคยพอ

---

## 1. กฎเป็นความเรียง และความเรียงไม่ทำงาน

กฎ MoMA อยู่ใน `docs/lessons/2026-08-20-the-moma-pass.md` — บทเรียนที่บรรยายการแก้หกจุด ซึ่งทำครั้งเดียว บนหน้าเดียว

ตรวจเมื่อ 2026-09-08:

- `grep -ci moma CLAUDE.md` → **0** กฎไม่อยู่ในไฟล์ที่เอเจนต์ทุกตัวอ่าน
- ไม่มีเทสต์ ไม่มีกฎลินต์ ไม่มีงาน CI ในที่เก็บทั้งสองที่เอ่ยการจัดแนว
- บทเรียนนั้นเขียนปิดท้ายเองว่าการตรวจ **ทำแค่หน้าแรก** และระบุ `/trade`, `/signals`, `/portfolio`, `/simulate`, `/plan` ว่าไม่เคยถูกตรวจ

กฎที่ไม่มีอะไรบังคับ ถูกเถียงใหม่โดยทุกคอมโพเนนต์ใหม่ และทุกคอมโพเนนต์ใหม่ถูกเขียนโดยคน (หรือสิ่ง) ที่ไม่ได้อ่านบทเรียน การแก้ครั้งแรกเป็นจริง มันแค่ไม่มีกลไกให้แผ่ไป

---

## 2. ไม่มีชุดระยะ ดังนั้นการจัดแนวเป็นไปไม่ได้ทางเลขคณิต

สองชิ้นลงขอบเดียวกันเมื่อค่าระยะของมันมาจากชุดเล็กชุดเดียวกัน วัดข้าม `src/`:

| | daytraders | day2 |
|---|---|---|
| ค่าระยะที่ต่างกัน | **86** | 25 |
| จำนวนครั้งที่ใช้ | 5,028 | 402 |
| หลุดกริด 4px | **40.1%** | 37.1% |
| โทเคนระยะที่นิยามไว้ | **1** (`--gap: 12px`) | 0 |

ค่าที่หลุดรวม 1, 3, 5, 7, 9, 11, 13, 15, 18, 22, 26, 34, 35, 37, 38, 42, 45, 50, 58, 70, 95, 97, 110, 118, 222px

คุณจัดแนว 86 ค่าไม่ได้ ไม่ใช่ด้วยความระวังมากขึ้น ไม่ใช่ด้วยการรีวิวมากขึ้น ชุดต้องปิดก่อน นั่นคือกฎข้อ II และมันเป็นเงื่อนไขของทุกกฎที่เหลือ

---

## 3. จุดเริ่มหลักของหน้าเองก็ไม่อยู่บนสเกล

```css
--cockpit-x: 22px;   /* จุดเริ่มแนวนอนที่ทุกระนาบรับไป */
```

22 ไม่ใช่ผลคูณของ 4 คอมเมนต์เหนือมันใน `globals.css` ถูกที่ว่าทุกระนาบอ่านค่านี้ «เพื่อให้ขอบทับกันโดยโครงสร้าง» และพวกมันทับกันจริง ที่ค่าซึ่งระยะอื่นในระบบไปถึงไม่ได้ ตัวเลขนั้นใช้ได้ ค่าของมันไม่อยู่บนสเกล

---

## 4. เส้นผมขยับทุกอย่างที่มันกรอบ

นี่คือหัวใจเชิงกล และมันมองไม่เห็นในการรีวิวโค้ด

วัดสดที่ 1280×900:

| คอนเทนเนอร์ | มันตั้งจุดเริ่มอย่างไร | ซ้ายของกล่อง | ซ้ายของลูกตัวแรก |
|---|---|---|---|
| `.rams-masthead` | `padding-left: 22px` ไม่มีเส้นขอบ | 0 | **22** |
| `.rams-cell-grid` | `border: 1px`, `padding-left: 0` | 22 | **23** |
| `.picks-grid` | `border: 1px`, `padding-left: 0` | 22 | **23** |

ทั้งสองคอนเทนเนอร์ต้องการจุดเริ่มเดียวกัน แยกกันดู ทั้งคู่ «ถูก» แต่เส้นขอบร่วมเลย์เอาต์ ส่วนแพดดิงค่าเดียวกันไม่ร่วม ดังนั้นทุกช่องในกริดที่มีกรอบ นั่งเข้าไปด้านในของคำเหนือมันพอดี 1px

ตอนวัด: **องค์ประกอบ 124 ชิ้นที่ x=22, 62 ชิ้นที่ x=23**

แพตเทิร์นที่ทำให้เกิดเป็นแพตเทิร์นที่ดี — กริดเส้นผม ที่ `gap: 1px` ทับ `background: var(--line)` วาดเส้นภายในทุกเส้นโดยไม่ต้องมาร์กอัปเพิ่ม:

```css
.rams-cell-grid {
  display: grid;
  gap: 1px;
  background: var(--line);
  border: 1px solid var(--line);   /* บรรทัดนี้ดันลูกทุกตัว */
}
```

การแก้คือหนึ่งพร็อพเพอร์ตี ให้เงานับเป็นกรอบ เงาทาโดยไม่กินพื้นที่

```css
  box-shadow: inset 0 0 0 1px var(--line);
```

ใช้สดแล้ว การเลื่อนของลูกในกริดจาก **1px เป็น 0** และดึงสิบองค์ประกอบขึ้นจุดเริ่มร่วม (x=22: 124 → 134)

## 5. …และการแก้ตรงจุดทำให้ทั้งหน้าแย่ลง

นี่คือข้อค้นที่สำคัญที่สุด และเป็นเหตุที่การกวาด MoMA ก่อนหน้าถอยกลับเรื่อย

เมื่อใช้การแก้เดียวกันสด จำนวนคู่ที่เกือบตรงทั้งหน้า **สูงขึ้น**:

```
ก่อนแก้ : คู่ขอบที่เกือบตรง 856 คู่
หลังแก้ : คู่ขอบที่เกือบตรง 905 คู่   (+49)
```

การแก้ที่ระดับคอนเทนเนอร์ถูก และทำสิ่งที่มันอ้าง แต่การดึงองค์ประกอบครอบครัวหนึ่งขึ้นจุดเริ่ม ขยับลูกหลานของพวกมันไป 1px ด้วย และลูกหลานเหล่านั้นไปลงห่าง 1px จาก *อีกครอบครัว* ที่ไม่เคยอยู่บนจุดเริ่มเหมือนกัน ระยะเลื่อน 1px ไม่ใช่บั๊กในสองคอมโพเนนต์ มันคือสภาพแวดล้อมของหน้าที่มีค่าระยะ 86 ค่าและจังหวะคอลัมน์ 31 แบบ

**การจัดแนวซ่อมทีละองค์ประกอบไม่ได้** ทุกการแก้เฉพาะที่กระจายความคลาดเคลื่อนใหม่ มันซ่อมได้โดยการปิดชุดค่า — จุดเริ่มเดียว ระยะสิบห้าค่า ความหนาแน่นสี่ค่า (192, 296, 400, 608) — แล้วถือชุดนั้นให้ปิดด้วยตัวตรวจที่รันทุกคอมมิต

นั่นคือที่เก็บนี้

## สิ่งที่ยึดอยู่จริง

| ความล้มเหลว | กฎ | ถูกบังคับโดย |
|---|---|---|
| กฎอยู่ในความเรียง | — | `lint/` ใน CI และเส้นฐานที่ลดได้อย่างเดียว |
| ชุดระยะเปิด | II | `spacing-scale` |
| จุดเริ่มไม่อยู่บนสเกล | I | `spacing-scale` บนโทเคน |
| เส้นผมดันลูก | I | `origin-mechanism` ถูกเอ่ยใน LAWS.md ยังไม่ถูกเขียน |
| จังหวะคอลัมน์ 31 แบบ | V | `grid-density` |
| ช่องเหลือ | IV | `orphan-grid` (ตอนรัน) |
| แถวสูงไม่เท่า | VI | `ragged-row` (ตอนรัน) |
| ระยะเลื่อน 1–6px | VII | `near-miss` (ตอนรัน) |

ครึ่งสถิตรันบนซอร์สได้ CI รันมันบน `examples/` แล้วรัน `lint/self-check.mjs` กับ `lint/laws-check.mjs` ครึ่งตอนรันไม่รัน จนกว่าจะมีคนวาง `audit/near-miss.browser.js` ลงคอนโซล คู่ที่เกือบตรง ช่องเหลือ และแถวสูงไม่เท่า ไม่มีอยู่จนกว่าเบราว์เซอร์จะจัดหน้า ซึ่งเป็นเหตุที่การอ่านโค้ดไม่เคยจับพวกมัน `origin-mechanism` ตัวตรวจที่ตั้งชื่อไว้สำหรับเส้นผมที่ดันลูก ยังไม่ได้ถูกเขียน
