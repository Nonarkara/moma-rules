# กริด ที่คำนวณได้

หน้านี้ไม่มีรสนิยม ทุกตัวเลขถูกคำนวณจากค่าตั้งต้นสี่ค่า และการคำนวณตรวจได้

คำสั่งที่ตรวจคือ `node lint/self-check.mjs` มันพิสูจน์ว่า `lint/scale.mjs` สอดคล้องกับตัวเอง มันไม่อ่านหน้านี้

## ค่าตั้งต้นสี่ค่า

```
คอลัมน์   12
ความกว้างคอลัมน์    88px
ร่อง       16px
ขอบหน้า    24px
```

## หน้า

```
  12 คอลัมน์ ×  88px   = 1056
+ 11 ร่อง ×  16px      =  176
─────────────────────────────
  ความกว้างเนื้อหา      = 1232
+  2 ขอบ × 24px        =   48
─────────────────────────────
  ความกว้างหน้า         = 1280
```

1280 ไม่ได้ถูกเลือกเพราะเป็นความกว้างเดสก์ท็อปที่คนใช้กัน มัน **ได้มาเอง** จากการเลือกคอลัมน์ 88 (= 4 × 22) กับร่อง 16 ถ้าเลือกคอลัมน์ 80 หน้าจะเป็น 1184 ประเด็นคือความกว้างหน้าเป็นผล ไม่ใช่ข้อมูลเข้า ดังนั้นเนื้อหาไม่ต้องถูกเขี่ยให้พอดี

## ทำไมสิบสอง

สิบสองคือจำนวนที่มีประโยชน์ที่เล็กที่สุด ซึ่งมีตัวหารที่ไม่ใช่หนึ่งและตัวมันเองสี่ตัว: 2, 3, 4, 6 ทุกตัวให้ช่วงที่เป็น **จำนวนเต็ม**

| ต้องการ | ช่วง | ความกว้าง | ตรวจ |
|---|---|---|---|
| หนึ่งในสิบสอง | 1 | 88 | 12 × 88 + 11 × 16 = 1232 |
| หนึ่งในหก | 2 | 192 | 6 × 192 + 5 × 16 = 1232 |
| หนึ่งในสี่ | 3 | 296 | 4 × 296 + 3 × 16 = 1232 |
| หนึ่งในสาม | 4 | 400 | 3 × 400 + 2 × 16 = 1232 |
| ครึ่ง | 6 | 608 | 2 × 608 + 1 × 16 = 1232 |
| เต็ม | 12 | 1232 | 1 × 1232 = 1232 |

`ช่วง(s) = s × 88 + (s − 1) × 16`

ทุกแถวกลับมาที่ 1232 พอดี ไม่มีเศษให้ดูด ดังนั้นไม่มีคอมโพเนนต์ที่ต้อง «เขี่ย» และการเขี่ยคือที่มาของระยะเลื่อน 1px

## ความหนาแน่น ที่คำนวณได้

กริดที่ตอบสนองความกว้างมักเขียนว่า `repeat(auto-fit, minmax(Xpx, 1fr))` และ X มักถูกเลือกด้วยตา นั่นคือแหล่งเดียวที่ใหญ่ที่สุดของการไม่ตรงแนวในโค้ดขนาดใหญ่ เพราะ X แต่ละค่าลงที่จำนวนคอลัมน์ของตัวเอง

ทางแก้คืออนุญาตเฉพาะ X ที่ **เป็นความกว้างของช่วง** ตรวจแล้วทุกวิวพอร์ตที่ใช้กัน (ขอบหน้าเป็น 16 เมื่อต่ำกว่า 768 และเป็น 24 เมื่อสูงกว่า):

| minmax | 390 | 768 | 1024 | 1280 | 1440 | หาร 12 ลงตัว? |
|---|---|---|---|---|---|---|
| 88 (ช่วง 1) | 3 | 7 | 9 | 12 | 13 | **ไม่** |
| **192** (ช่วง 2) | 1 | 3 | 4 | 6 | 6 | ใช่ |
| **296** (ช่วง 3) | 1 | 2 | 3 | 4 | 4 | ใช่ |
| **400** (ช่วง 4) | 1 | 1 | 2 | 3 | 3 | ใช่ |
| **608** (ช่วง 6) | 1 | 1 | 1 | 2 | 2 | ใช่ |

ความหนาแน่นที่ถูกกฎหมายสี่ค่า ทุกค่า ทุกความกว้าง ลงที่จำนวนที่หาร 12 ลงตัว ดังนั้นขอบช่องตกบนเส้นคอลัมน์หลัก และชุดสิบสองชิ้นเติมมันได้โดยไม่เหลือช่อง (กฎข้อ IV)

ช่วง 1 (88px) ถูกกันออก มันให้ 7 และ 13 คอลัมน์ ซึ่งไม่มีอะไรจัดแนวเข้าด้วยได้ สิบสองคอลัมน์คือกริดสำหรับ *วาด* มันไม่ใช่ความหนาแน่น auto-fit ที่ถูกกฎหมาย

จำนวนคอลัมน์ใช้สูตรเดียวกับ `lint/self-check.mjs`: ขอบหน้าเป็น 16 เมื่อวิวพอร์ตต่ำกว่า 768 นอกนั้นเป็น 24 จำนวนคอลัมน์คือ `max(1, floor((วิวพอร์ต − 2 × ขอบ + ร่อง) / (ค่าต่ำสุด + ร่อง)))`

## เทียบกับสิ่งที่โค้ดทำอยู่ในวันนี้

daytraders ใช้ **ค่าต่ำสุดของ minmax ต่างกัน 31 ค่า** — 5, 38, 42, 56, 64, 72, 78, 88, 90, 92, 96, 100, 104, 110, 118, 120, 130, 140, 150, 160, 180, 190, 200, 220, 240, 260, 280, 300, 320, 360, 440 — ให้ **จำนวนคอลัมน์ต่างกัน 12 แบบบนหน้า 1280px หน้าเดียว** ส่วนที่เป็น 5, 7 และ 9 คอลัมน์ ไม่สามารถใช้ขอบด้านในร่วมกับอะไรได้ และไม่มีอันไหนเติมได้โดยไม่เหลือช่อง

ตัวเลขเหล่านี้มาจากบันทึกการวัดเมื่อ 2026-09-08 ไม่ใช่การวัดซ้ำของฉบับนี้

## จอแคบ

ต่ำกว่า 768 ขอบหน้าลดเหลือ 16 และคอลัมน์เป็นของไหล

```
ความกว้างคอลัมน์ = (100vw − 32 − (จำนวนคอลัมน์ − 1) × 16) / จำนวนคอลัมน์
```

*คอลัมน์* เป็นของไหล **ร่องกับขอบหน้าอยู่บนสเกล** นี่คือเส้นที่ต้องถือ: ความกว้างไหลได้ ระยะไหลไม่ได้ เพราะระยะคือสิ่งที่คอมโพเนนต์ข้างเคียงสองตัวต้องตกลงกัน

## ใน CSS

```css
:root {
  --col: 88px;
  --gutter: 16px;
  --margin: 24px;
  --content: 1232px;

  --span-2: 192px;   /* หนึ่งในหก */
  --span-3: 296px;   /* หนึ่งในสี่ */
  --span-4: 400px;   /* หนึ่งในสาม */
  --span-6: 608px;   /* ครึ่ง */
}

.page {
  max-width: var(--content);
  margin-inline: auto;
  padding-inline: var(--margin);
}

/* กริดตอบสนองความกว้างที่ถูกกฎหมาย มีสี่แบบนี้เท่านั้น */
.grid-sixths   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-2), 1fr)); }
.grid-quarters { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-3), 1fr)); }
.grid-thirds   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-4), 1fr)); }
.grid-halves   { display: grid; gap: var(--gutter);
                 grid-template-columns: repeat(auto-fit, minmax(var(--span-6), 1fr)); }
```

## กริดเส้นผม แบบที่ทำถูก

แพตเทิร์นที่ `gap: 1px` ทับพื้นที่มีสี แล้วเส้นภายในทุกเส้นโผล่มา เป็นแพตเทิร์นที่ดี และควรเก็บไว้ สิ่งที่เปลี่ยนคือกรอบ — กฎข้อ I:

```css
/* ผิด — เส้นขอบดันลูกทุกตัวไป 1px */
.hairline-grid { display: grid; gap: 1px; background: var(--line);
                 border: 1px solid var(--line); }

/* ถูก — กรอบถูกทา โดยไม่กินพื้นที่เลย์เอาต์ */
.hairline-grid { display: grid; gap: 1px; background: var(--line);
                 box-shadow: inset 0 0 0 1px var(--line); }
```

ทั้งสองวาดกรอบที่ตาเห็นเหมือนกัน มีแต่แบบที่สองที่ปล่อยลูกไว้บนจุดเริ่มของหน้า

## สิ่งที่หน้าสาธิตจัดได้จริง

CSS ด้านบนคือสิ่งที่ `examples/index.html` ใช้ ไฟล์นั้นยังตั้ง `box-sizing: border-box` บนทุกองค์ประกอบ วัดเมื่อ 2026-10-12 ใน Chrome แบบ headless วิวพอร์ต 1280×900 ธีมมืด: กล่องตาม border-box ของหน้ากว้าง 1232px แพดดิงข้างละ 24px ความกว้างด้านใน 1184px

`lint/scale.mjs` ยังบอกว่าหน้ากว้าง 1280 คือเนื้อหา 1232 บวกขอบสองข้างข้างละ 24 ภายใต้ `border-box` กล่องนั้นจะกว้าง 1280 ก็ต่อเมื่อ `max-width` เป็นความกว้างหน้า 1280 ไม่ใช่ความกว้างเนื้อหา 1232 เลขคณิตในหน้านี้คือแหล่งความจริง ไฟล์สาธิตยังไม่ได้จัดหน้าให้กว้าง 1280 ลินเตอร์สถิตไม่ดู `max-width` ดังนั้น CI ยังเขียว
