# กฎ ต่อตัวตรวจ ต่องานวิจัย

**วันตรวจ:** 2026-09-10 ทำซ้ำได้ด้วย `node lint/laws-check.mjs`
**อ่านอีกครั้ง:** 2026-10-12 กับซอร์สปัจจุบันและการเรนเดอร์หนึ่งครั้ง ต้นฉบับอังกฤษอยู่ที่ [law-to-check.md](law-to-check.md) ถ้าตัวเลขไม่ตรงกัน ให้ยึดโค้ดกับฉบับอังกฤษ

> «ทุกกฎข้างล่างมีตัวตรวจ — รหัสกฎที่บังคับมัน กฎที่ไม่มีตัวตรวจเป็นความปรารถนา และความปรารถนาคือเหตุที่การกวาด MoMA สามรอบก่อนไม่อยู่»
> — [LAWS.md](../LAWS.md)

ประโยคนั้นคือคำสัญญาใจกลางของที่เก็บ หน้านี้ทดสอบมัน เพราะคำสัญญาเรื่องการบังคับ ตัวมันเองเป็นข้ออ้างที่วัดได้ สามอย่างกลายเป็นจริง และไม่น่ายินดี

1. **ตัวตรวจสถิตของกฎข้อ I ไม่มีอยู่** `origin-mechanism` ถูกเอ่ยใน `LAWS.md` และไม่มีที่ไหนทำให้เกิด กฎที่เป็นเหตุให้ที่เก็บนี้มีชื่อ ถูกบังคับด้วยความปรารถนา
2. **สี่ข้อถูกบังคับโดยการวางสคริปต์ลงคอนโซลเท่านั้น** CI รันลินเตอร์สถิตบน `examples/` แล้วรัน `lint/self-check.mjs` กับ `lint/laws-check.mjs` มันไม่เคยรันผู้ตรวจตอนหน้าถูกจัดแล้ว ดังนั้นข้อ I, IV, VI และ VII ไม่มีการบังคับอัตโนมัติเลย
3. **ยังมีตัวตรวจหนึ่งตัวที่ขัดกับกฎที่มันบังคับ** การใช้น้ำหนักเส้นเน้นที่กฎข้อ VIII อ้างเอง ทำให้เกิดรายการ `hairline` ข้อขัดแย้งที่สอง — กฎข้อ V สั่ง 160 / 220 / 280 — เป็นจริงในเช้าของวันตรวจนี้ และถูกปิดในวันเดียวกัน บันทึกของความล้มเหลวนั้นเก็บไว้ข้างล่าง มันไม่ใช่ข้อความปัจจุบันของ `LAWS.md`

## ข้อขัดแย้งสองเรื่อง เรื่องหนึ่งเป็นประวัติแล้ว

### ข้อ V เคยสั่งตัวเลขที่ `scale.mjs` เรียกว่าตัวอย่างของสิ่งที่พัง

เช้าวันตรวจ `LAWS.md` ข้อ V ว่า *«หน้าหนึ่งใช้ได้สามค่า: 160, 220, 280»*

`lint/scale.mjs` ในคอมเมนต์ของ `DENSITY` เองว่า ค่าต่ำสุดที่ไม่ใช่ความกว้างของช่วง (160, 220, 240…) ลงที่ 5, 7, 9, 11 คอลัมน์ ซึ่งหน้า 12 คอลัมน์จัดแนวเข้าด้วยไม่ได้

กฎสั่งสามค่าที่แหล่งความจริงยกเป็นของพังพอดี สไตล์ชีตที่ทำตามกฎเป๊ะ:

```css
.tight  { grid-template-columns: repeat(auto-fit, minmax(160px, 1fr)); }
.normal { grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); }
.wide   { grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)); }
```

```
$ node lint/moma-lint.mjs that-file --strict
  MoMA LINT — 3 violations
        3  grid-density
      only 608/400/296/192px are permitted column minimums
```

**ทำตามกฎ แล้วบิลด์ไม่ผ่าน** `self-check.mjs` รายงานว่า «การคำนวณทุกชุดตรง» ตลอด เพราะมันตรวจ `scale.mjs` กับตัวเอง และไม่เคยอ่าน `LAWS.md` ตัวตรวจมองไม่เห็นเอกสารที่มันอ้างว่าปกป้อง

แก้เมื่อ 2026-09-10: ข้อ V ตอนนี้เขียนความหนาแน่นที่คำนวณจากช่วงคอลัมน์ ความเรียงผิด `scale.mjs`, `docs/grid.md` และลินเตอร์เห็นตรงกันอยู่แล้ว `lint/laws-check.mjs` อ่านความเรียงแล้ว ข้อแบบนี้กลับมาเงียบ ๆ ไม่ได้อีก

### ข้อ VIII ห้ามน้ำหนักเน้นที่มันยกเป็นบรรทัดฐาน

ข้อ VIII: *«น้ำหนักเส้นเดียว (1px) และสีเส้นเดียว เส้นขอบ 2px คือภาษาออกแบบที่สองที่กำลังเถียงกับภาษาแรก»* สองบรรทัดถัดไป เป็นหลักฐานของมันเอง: *«เส้นเป็น `.1rem` (1px) ทึบ `.2rem` กับ `.3rem` มีไว้เน้นโดยตั้งใจ ไม่เคยเป็นเส้นขอบปริยาย»*

```
$ node lint/moma-lint.mjs a-file-using-2px-and-3px-emphasis --strict
  MoMA LINT — 2 violations
        2  hairline
      one border weight only (1px) — 2px is a second language
```

พฤติกรรมของ MoMA ที่วัดได้ (รหัสวิจัย R7) คือ **ค่าปริยายหนึ่งค่า บวกสถานะเน้นสองสถานะ** กฎยุบอันนั้นเหลือค่าที่อนุญาตค่าเดียว จงใจไม่ปิด: นี่เป็นการทำให้เข้มขึ้น ไม่ใช่เลขคณิตผิด ดู [ข้อเสนอ v2](proposals/v2-architecture.md) ซึ่งยังเป็นอังกฤษ

| R9 ชุดอัตราส่วนที่ปิดแล้ว | วิจัยแล้ว · **ไม่มีกฎ · ไม่มีตัวตรวจ** |

**นี่คือสิ่งที่ [ข้อเสนอ v2](proposals/v2-architecture.md) มีไว้จริง** และมันกลับลำดับของข้อเสนอนั้นเอง v2 ขอสามชั้นบนพื้น (`LAWS` / `MOVES` / `REGISTERS`) พื้นมีตัวตรวจลวงในข้อ I สี่ข้ออยู่นอก CI และหนึ่งตัวตรวจที่ขัดกับกฎของมัน **ปิดพื้นก่อน แล้วค่อยเพิ่มชั้น** คำศัพท์การจัดภาพที่กองบนฐานซึ่งไม่ถูกบังคับ คือการกวาดด้วยความเรียงครั้งที่สี่ สวมหมวกใบใหม่

## สิ่งที่พบในวันตรวจ

ประโยคก่อนหน้าของหน้านี้บอกว่า `lint/moma-lint.mjs` กับ `audit/near-miss.browser.js` ชี้ไปที่ `audit/near-miss.mjs` ทั้งคู่ พวกมันไม่ชี้ ลินเตอร์ชี้ไปที่ `audit/near-miss.browser.js` ไฟล์นั้นบอกว่าไม่มีตัวรันแบบโปรแกรม ซึ่งเป็นเหตุที่ครึ่งตอนรันไม่อยู่ใน CI ไม่มีอะไรใน `lint/` หรือ `audit/` เอ่ย `audit/near-miss.mjs`

## อ่านอีกครั้งเมื่อ 2026-10-12

`examples/index.html` ถูกเรนเดอร์ใน Chrome แบบ headless วิวพอร์ต 1280×900 ค่า `data-theme="dark"` โหลด IBM Plex แล้ว วันเดียวกัน `node lint/moma-lint.mjs examples --strict` รายงาน 0 รายการ

| อะไร | วัดได้ |
|---|---|
| `h1` | 64px / 65.28px น้ำหนัก 700 ประกาศคือ `clamp(32px, 7vw, 64px)` กับ `line-height: 1.02` |
| สองกรอบ | ลูกที่มีเส้นขอบ `+1px` ลูกที่ใช้เงาด้านใน `0px` |
| `.page` | กล่องตาม border-box 1232px แพดดิง 24px + 24px ความกว้างด้านใน 1184px |
| `.quote` | `border-left-width: 1px`, `padding-left: 16px` |

ชื่อเรื่องเป็นขนาดที่สี่ซึ่ง `type-scale` มองไม่เห็น เพราะตัวตรวจจับคู่ `font-size: Npx` เปล่า ๆ และประกาศนี้เป็น `clamp()` เส้นของคำพูดคือการดันที่กฎข้อ I ห้าม ที่น้ำหนักซึ่ง `hairline` อนุญาต ตัวตรวจที่ต้องสังเกตคือ `origin-mechanism` และมันไม่ได้ถูกเขียน

`lint/laws-check.mjs` จับครึ่งระยะบรรทัดของ `micro 11/16` แล้วไม่เทียบกับ `LEADING` `type-scale` ไม่เคยอ่าน `line-height`

`lint/moma-lint.mjs` เดิน `.tsx`, `.ts`, `.jsx`, `.js`, `.css`, `.scss` และ `.html` มันไม่อ่าน `.mjs` ดังนั้นตัวตรวจไม่ตรวจตัวเอง

กฎข้อ X ให้ป้ายหมวดเป็น «คิ้ว 9px» 9 ไม่ได้อยู่ใน `TYPE` (11 / 14 / 32) `font-size: 9px` แพ้ `type-scale` ประโยคนั้นสั่งขนาดที่ระบบที่เหลือห้าม จดไว้ตามที่พบ

`package.json` มีสองสคริปต์ `lint` รัน `node lint/moma-lint.mjs .` `check` รัน `node lint/self-check.mjs` เท่านั้น ไม่มีสคริปต์ `audit` CI ใน `.github/workflows/moma.yml` รันลินต์เข้มของ `examples/`, `self-check` และ `laws-check` มันไม่วางสคริปต์เบราว์เซอร์
