# กฎ MoMA

กฎสิบข้อสำหรับหน้าจอ และตัวตรวจที่ทำให้บิลด์ไม่ผ่านเมื่อกฎถูกละเมิด สามรอบก่อนหน้าเขียนกฎเดียวกันนี้เป็นความเรียง หน้ากระดาษเลื่อนกลับมาทุกรอบ รอบนี้ตัวเลขอยู่ใน `lint/scale.mjs` ความเรียงมีหน้าที่พูดตัวเลขให้ตรง แล้วถูกตรวจกับโค้ด

![หน้าสาธิต ธีมมืด วิวพอร์ต 1280×900 กรอบที่มีเส้นขอบรายงานว่าลูกถูกดันไป +1px กรอบที่ใช้เงาด้านในรายงาน 0px](docs/specimen.png)

`examples/index.html` ใน Chrome แบบ headless วิวพอร์ต 1280×900 ค่า `data-theme="dark"` โหลด IBM Plex Sans กับ IBM Plex Mono แล้ว วันที่ 2026-10-12 สองกรอบคือหน้ากำลังวัดลูกของตัวเอง [เปิดหน้านี้](examples/index.html)

รูปนี้ไม่ใช่สูตร 1280 ในวิวพอร์ตนี้ กล่องแบบ border-box ของหน้ากว้าง **1232px** แพดดิงข้างละ 24px ความกว้างด้านใน **1184px** ชื่อเรื่องคำนวณได้ **64px / 65.28px** ทั้งสองอย่างอยู่ข้างล่าง ในส่วนที่ตัวตรวจมองไม่เห็น

> «ของทุกอย่างต้องจัดแนวให้ตรง ห้ามมีขอบหลุดให้คนเห็นว่าคนทำยังเป็นมือสมัครเล่น»
>
> นี่คือคำกล่าวของ Dr Non เมื่อ 2026-08-20 ที่เรียบเรียงเป็นไทยสำหรับฉบับนี้ ประโยคอังกฤษเดิมคือ MoMA rules dictate that everything has to be aligned and there should be no loose edges to show that the builder is an amateur.

[กฎสิบข้อ](LAWS.th.md) · [วิธีที่ช่างทำงาน](BUILDER.th.md) · [กริด ที่คำนวณได้](docs/grid.th.md)

## หน้าหนึ่ง กับตัวเลขสี่ชุด

ตัวเลขมาจาก `lint/scale.mjs` คำสั่ง `node lint/self-check.mjs` คำนวณซ้ำให้

| | |
|---|---|
| คอลัมน์ ร่อง ขอบหน้า | 88, 16, 24 |
| ความกว้างเนื้อหา | 12 × 88 + 11 × 16 = **1232** |
| ความกว้างหน้า | 1232 + 2 × 24 = **1280** |
| ระยะ | `0  4  8  12  16  20  24  32  40  48  64  80  96  120  160` |
| ขนาดตัวอักษร / ระยะบรรทัด | 11/16, 14/20, 32/36 |
| ค่าต่ำสุดของ `minmax` ที่ใช้ได้ | 192, 296, 400, 608 |
| เส้นผม มุมมน | 1px และห้ามกินพื้นที่เลย์เอาต์ มุมมนเป็น 0 วงกลมจริงได้รับการยกเว้น |

กฎข้อ V เคยเขียน 160 / 220 / 280 จนถึง 2026-09-10 สามค่านี้คือตัวอย่างใน `scale.mjs` ว่าอะไรทำให้หน้า 12 คอลัมน์จัดแนวไม่ได้ ตอนนี้กฎเขียนความกว้างของช่วงคอลัมน์

## สิ่งที่รันจริง

| คำสั่ง | มันอ่านอะไร |
|---|---|
| `npm run lint` | `node lint/moma-lint.mjs .` กฎแบบสถิต เทียบกับเส้นฐานถ้ามี |
| `npm run check` | `node lint/self-check.mjs` เท่านั้น มันไม่เปิด `LAWS.md` |
| `node lint/laws-check.mjs` | [LAWS.md](LAWS.md) ฉบับอังกฤษ เทียบกับ `lint/scale.mjs` ไม่มีสคริปต์ npm ห่อมัน |
| วาง [`audit/near-miss.browser.js`](audit/near-miss.browser.js) ลงคอนโซล | ขอบหลังจากจัดหน้าแล้ว ไม่มีตัวรัน และไม่อยู่ใน CI |

CI คือ [`.github/workflows/moma.yml`](.github/workflows/moma.yml) ตอน push และ pull request มันรันสามอย่าง: `node lint/moma-lint.mjs examples --strict`, `node lint/self-check.mjs`, `node lint/laws-check.mjs`

กฎสถิตที่ลินเตอร์ส่งได้: `spacing-scale`, `grid-density`, `type-scale`, `radius-zero`, `hairline`

กฎที่รายงานได้เมื่อวางสคริปต์: `near-miss`, `orphan-grid`, `ragged-row`

`origin-mechanism` ถูกเอ่ยในกฎข้อ I และทำเครื่องหมายว่า **ยังไม่ถูกเขียน** `laws-check` ยอมรับ เพราะกฎบอกไว้ในข้อความของมันเอง

## สิ่งที่ตัวตรวจมองไม่เห็น

บิลด์เขียวได้ ทั้งที่หน้ายังผิด ช่องว่างต่อไปนี้อ่านจากซอร์สและจากรูปด้านบน เมื่อ 2026-10-12

- **ตัวตรวจสถิตของกฎข้อ I ไม่มีอยู่** บทสรุปที่แพงที่สุด — เส้นผมห้ามกินพื้นที่เลย์เอาต์ — ยังเป็นความปรารถนา คำพูดบนหน้าสาธิตเองเป็น `border-left: 1px` กฎ `hairline` อนุญาตน้ำหนักนี้ ไม่มีอะไรใน CI ถามว่าเส้นนั้นดันคำออกไปหรือเปล่า
- **สี่ข้อเป็นสคริปต์ที่ต้องวางลงคอนโซล** ข้อ I, IV, VI และ VII ไม่รันใน CI ขอบที่ห่าง 1–6px ช่องที่เติมไม่เต็ม และแถวที่สูงไม่เท่ากัน เกิดหลังเบราว์เซอร์จัดหน้าแล้วเท่านั้น
- **`type-scale` อ่านเฉพาะ `font-size: Npx` เปล่า ๆ** ชื่อเรื่องเป็น `clamp(32px, 7vw, 64px)` กับ `line-height: 1.02` ที่ 1280×900 นั่นคือ 64px บน 65.28px วันเดียวกัน ลินต์เข้มของ `examples/` รายงาน 0 รายการ `laws-check` จับระยะบรรทัดใน `micro 11/16` ได้ แล้วไม่เอาไปเทียบกับ `LEADING`
- **กฎข้อ VIII ยังเถียงกับตัวเอง** ความเรียงอ้างเส้นเน้น 2px และ 3px ของ MoMA ลินเตอร์ปฏิเสธทุกน้ำหนักที่ไม่ใช่ 1px ข้อขัดแย้งนี้เปิดไว้โดยตั้งใจ ข้อของกฎ V ปิดแล้ว
- **ลินเตอร์ไม่อ่าน `.mjs`** มันเดิน `.tsx`, `.ts`, `.jsx`, `.js`, `.css`, `.scss`, `.html` ตัวตรวจไม่ตรวจตัวเอง
- **ไม่มี `npm run audit`** ประโยคเก่าใน [BUILDER.md](BUILDER.md) เคยบอกว่ามี

ตารางเต็ม รวมวันที่กฎข้อ V ทำให้หน้าที่ทำตามกฎบิลด์ไม่ผ่าน อยู่ที่ [docs/law-to-check.th.md](docs/law-to-check.th.md)

กฎข้อ X — เลขตัวหนึ่งบนจอหนึ่งไม่พูดซ้ำ และให้ลำดับชั้นตามสิ่งที่ผู้อ่านมาหา — ไม่มีตัวตรวจ มันอยู่ท้ายสุด เพื่อให้เก้าข้อแรกใช้ความสนใจของเครื่อง แล้วเหลือข้อนี้ให้คน

## เอาไปใช้กับโค้ดที่เลอะแล้ว

อย่าเปิด `--strict` เป็นอย่างแรก มันจะถูกปิดภายในวันเดียว จดหนี้ไว้ แล้วให้มันลดได้อย่างเดียว

```bash
node lint/moma-lint.mjs src --update-baseline   # จดหนี้ของวันนี้
node lint/moma-lint.mjs src                     # ไม่ผ่านเฉพาะรายการใหม่
```

`--update-baseline` ปฏิเสธการเขียนไฟล์ที่ใหญ่ขึ้น หนี้ลดได้อย่างเดียว เพิ่มไม่ได้ ที่เก็บนี้ไม่มี `.moma-baseline.json` หน้าสาธิตสะอาดภายใต้กฎสถิตที่ลินเตอร์มองเห็น และไม่สะอาดในแบบที่หัวข้อก่อนหน้าเขียนไว้

- ตัวเลขจากของจริง — ค่าระยะ 86 ค่า, 40.1% หลุดกริด 4px, จุดเริ่มที่ 22px, ขอบ 124 ต่อ 62, คู่ขอบที่เกือบตรง 856 คู่ — มาจากการวัด day.nonarkara.org เมื่อ 2026-09-08 เขียนใน [docs/why-lines-dont-align.md](docs/why-lines-dont-align.md) ฉบับนี้ไม่ได้ไปวัดไซต์นั้นซ้ำ

- ตัวอักษรในฐานะปัญหาของผู้อ่าน: Robert Bringhurst, *The Elements of Typographic Style*, พิมพ์ครั้งที่สอง ปี 1997 หน้าที่เลือกคือ 17–33 และบทที่ 6 หน้า 93–117 ขอบเขต สัญญาอนุญาต และการไม่กล่าวว่าอ่านจบทั้งเล่ม อยู่ใน [docs/typography.md](docs/typography.md) ที่เก็บนี้ไม่มีไฟล์สแกนของหนังสือ และไม่มีการรับรองจากผู้เขียน
- วิธีอ่านเดียวกันคือทักษะพกพาที่ [skills/bringhurst-contextual-type/SKILL.md](skills/bringhurst-contextual-type/SKILL.md) และห้องอ่านของ [Palette](https://github.com/Nonarkara/palette) ที่ [colors.nonarkara.org/reading#typography](https://colors.nonarkara.org/reading#typography) ปกนี้ทำตามสัญญานั้นเท่าที่ไฟล์ Markdown ทำได้: ของจริงชิ้นเดียว ไม่มีแถวป้าย ไม่มีไล่สี ไม่มีอิโมจิแทนเครื่องหมาย
- หน้าสาธิตขอ IBM Plex Sans กับ IBM Plex Mono รูปตัวอย่างเรนเดอร์ตอนสองครอบครัวนี้โหลดแล้ว
